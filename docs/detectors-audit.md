# Аудит детекторов дипломного проекта `kleprer/diploma`

Сопоставление критериев трёх детекторов (`modalRestore`, `routingLoss`, `dynamicInsert`)
с требованиями веб-стандартов и профильных исследований.

**Скоуп: клавиатурное взаимодействие и поведение фокуса.**
Сценарии скринридеров (в частности, объявления через live-регионы) в модель оценки не входят.

Основание: `docs/protocol.md` (черновик протокола ручной разметки) + исходники детекторов.
Критерии и имена нарушений процитированы по протоколу; источники, помеченные «доп.»,
в протоколе не указаны и добавлены при аудите.

## 1. Детектор модальных окон — `modalRestore`

Источники по протоколу: S1, S2.

| ID | Критерий (по протоколу) | Имя нарушения | Соответствие |
|----|-------------------------|---------------|--------------|
| M1 | После открытия клавиатурой `document.activeElement` внутри диалога | `focus_not_moved_into_modal` | Полное. Прямое требование APG |
| M2 | Tab/Shift+Tab не переводят фокус на содержимое страницы за диалогом. Уход на `body` утечкой не считается: интерфейс браузера не является содержимым страницы, нативный `<dialog>` ведёт себя так же | `focus_leaks_out_of_modal` | Соответствует по существу; rationale в протоколе совпадает с логикой нативного `<dialog>` и вынесен в угрозы валидности |
| M3 | После закрытия фокус вернулся на триггер (если удалён — на логичный элемент) | `focus_not_restored` | Полное. Совпадает с F85, включая fallback |
| —  | Дополнительно в заметки: закрывается ли диалог по Escape | — | Наблюдение, не критерий. В вердикт не входит |

**Вердикт:** высокое соответствие. Единственное сужение — исключение `body` из M2 — осознанное и задокументировано в протоколе как угроза валидности.

## 3. Детектор динамической подгрузки — `dynamicInsert`

Источники по протоколу: S3, S7. Доп.: S6.

| ID | Критерий (по протоколу) | Имя нарушения | Соответствие |
|----|-------------------------|---------------|--------------|
| D1 | После вставки контента фокус не потерян (`activeElement` не `body`) | `focus_lost_after_load` | Полное. Совпадает с таксономией A11yLTLNav |

## 5. Границы применимости

1. Детектор не оценивает live-регионы — соответствует клавиатурному скоупу, но не покрывает опыт пользователей скринридеров.
2. Игнорирование `body` в M2 — осознанное сужение, зафиксировано в протоколе.
3. S3 для R1 и S6 для D2 — добавлены при аудите, в протоколе не указаны; при желании их можно внести в протокол, чтобы список источников совпадал.
4. Идентификатор S7 требует перепроверки по arXiv.
