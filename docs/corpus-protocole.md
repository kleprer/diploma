# Протокол формирования корпуса (черновик)

Статус: черновик, согласовать с научным руководителем до сбора данных.
Правило: этот документ фиксируется (коммитится) **до** запуска детектора на новых приложениях.

## 1. Цель корпуса

Набор реальных веб-приложений, на которых оценивается качество детектора и сравнение с axe-core
(см. `scope-and-rq.md`, RQ1 и RQ2). Собственные стенды (`modal-fixture`, `feed-fixture`) в основной результат **не входят**:
они нужны для проверки самого инструмента и помечаются `set=fixture` в `ground-truth.csv`.

## 2. Рамка выборки

- Открытые веб-приложения на React (в `package.json` есть `react` и `react-dom`).
- Источник: поиск по GitHub. Для каждого запроса записывается **текст запроса и дата**.
- Приложение берётся либо по commit-хешу (локальная сборка), либо как публичное демо
  (тогда записывается URL и **дата проверки**).

## 3. Критерии включения

1. Запускается из чистого клона не дольше 15 минут либо доступно как живое демо без платного аккаунта.
2. Не зависит от недоступных внешних сервисов (бэкенд, API, секреты).
3. Содержит хотя бы один из трёх объектов проверки:
   - клиентскую навигацию (ссылки, меняющие маршрут без перезагрузки документа);
   - модальное окно, открываемое управляющим элементом;
   - список с подгрузкой (кнопка «показать ещё» или бесконечная прокрутка).

## 4. Критерии исключения

- Репозиторий в архиве или приложение не собирается/не запускается.
- Интерфейс целиком на canvas (нет DOM для проверки).
- Требуются секреты или платный доступ.
- Каждое исключение записывается в журнал (раздел 8) с причиной и датой.

## 5. Страты (для разнообразия, чтобы выборка не была однородной)

- UI-библиотека: MUI, Ant Design, Radix/shadcn, Chakra, Bootstrap-подобные, самописный UI.
- Тип приложения: админка/дашборд, магазин, лента/соцсеть, документация/контент.
- Тип роутинга: React Router (history), hash-роутинг, Next.js.

## 6. Правило выбора внутри страты

Из отфильтрованного списка выбирается случайная подвыборка. Генератор случайных чисел и
**seed записываются** в таблицу корпуса. Если случайный выбор невозможен, используется порядок
по числу звёзд, и это явно указывается.

## 7. Правило перечисления сценариев (до запуска детектора)

- Роутинг: каждая ссылка основной навигации первого уровня (не более 3 на приложение).
- Модалки: каждый управляющий элемент, активация которого открывает элемент с `role="dialog"`
  при обходе страницы (не более 3 на приложение).
- Подгрузка: каждый список с видимой кнопкой «показать ещё» или бесконечной прокруткой (не более 2).
- Сценарии не выбрасываются после просмотра результата детектора.

## 8. Журнал исключений

| Приложение | Дата | Причина |
|---|---|---|
| RealWorld Conduit (gothinkster/react-redux-realworld-example-app) | (дата) | репозиторий в архиве; демо отдаёт 404; фронтенд завязан на общий API, который недоступен (ошибка запроса в middleware) |

## 9. Данные, записываемые для каждого приложения

Название, репозиторий, commit-хеш или URL демо с датой проверки, режим (dev/prod),
версия Playwright, страта, seed.

## 10. Целевой размер (предложение, согласовать)

Не менее 35 сценариев с нарушением и не менее 35 без нарушения на реальных приложениях
(расчёт: доверительный интервал Уилсона 95% с полушириной около ±0.10 при ожидаемой доле 0.9).
Ориентир по числу приложений: 25–30 приложений по 2–3 сценария.
Результаты по отдельным паттернам описывать как предварительные (интервалы шире).
